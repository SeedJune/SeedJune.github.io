## 计算机中的数字

### 数字表示方法

现代计算机存储和处理的信息用二值信号表示，这些微不足道的二进制数字被称为位（bit）。人们之所以使用二进制，而不使用我们更熟悉更自然的十进制数字，是因为二值信号能够很容易地被机器表示、存储和传输。
整数、浮点数、字符和机器指令在底层都是由 `0` 和 `1` 组成的位序列。单个的位通常不是很有意义，把位组合在一起并加以某种解释，就可以赋予位模式不同的含义。即同一串位本身没有固定含义，具体含义取决于程序如何解释它。例如，位模式 `01000001` 既可以表示十进制整数 `65`，也可以表示 ASCII 字符 `A`。

#### 计算机中的进制

计算机领域主要涉及二进制和十六进制。

对于一个 $w$ 位二进制数 $x_{w-1}x_{w-2}\cdots x_1x_0$，如果将其解释为无符号整数，它的值为：

$$
\sum_{i=0}^{w-1}x_i2^i
$$

例如：

$$
(10110)_2=1\times2^4+0\times2^3+1\times2^2+1\times2^1=22
$$

一个十六进制位正好对应四个二进制位，因此通常使用十六进制书写机器中的位模式。

| 十六进制 | 十进制 | 二进制 |
| --- | --- | --- |
| `0` | 0 | `0000` |
| `1` | 1 | `0001` |
| `2` | 2 | `0010` |
| `3` | 3 | `0011` |
| `4` | 4 | `0100` |
| `5` | 5 | `0101` |
| `6` | 6 | `0110` |
| `7` | 7 | `0111` |
| `8` | 8 | `1000` |
| `9` | 9 | `1001` |
| `A` | 10 | `1010` |
| `B` | 11 | `1011` |
| `C` | 12 | `1100` |
| `D` | 13 | `1101` |
| `E` | 14 | `1110` |
| `F` | 15 | `1111` |

二进制转十六进制时，从右向左每四位分成一组，不足四位时在左侧补零：

```text
1101011011₂
= 0011 0101 1011₂
= 0x35B
```

C 语言中常见的整数常量写法如下：

```c
int decimal = 42;       // 十进制
int octal = 052;        // 八进制，值为十进制 42
int hexadecimal = 0x2A; // 十六进制
```

其中 `0x` 或 `0X` 前缀表示十六进制，以 `0` 开头的整数字面量表示八进制。因此，C 语言中的 `010` 是十进制的 `8`，而不是十进制的 `10`。

### 数据存储

#### 位、字节与字长

- **位（bit）**：最小的信息单位，取值为 `0` 或 `1`。
- **字节（byte）**：机器寻址的基本单位，1 byte = 8 bits
- **字（word）**：处理器能够自然处理的数据大小。32 位机器的字长通常为 32 位，64 位机器的字长通常为 64 位。

字长会影响指针大小、虚拟地址空间大小以及处理器能够自然处理的整数范围。程序将内存看成一个很大的字节数组，每个字节都有唯一地址，这些地址的集合构成虚拟地址空间。

如果一个 4 字节对象的起始地址是 `0x100`，那么它会占用地址 `0x100` 到 `0x103`。指针保存的就是对象在虚拟地址空间中的地址。

```c
int x = 42;
int *p = &x;
```

不同平台上的 C 数据类型大小可能不同，应使用 `sizeof` 获取当前环境中的实际大小。在典型的 64 位 Linux 系统中，常见情况如下：

| C 类型 | 常见大小 |
| --- | ---: |
| `char` | 1 字节 |
| `short` | 2 字节 |
| `int` | 4 字节 |
| `long` | 8 字节 |
| `long long` | 8 字节 |
| `float` | 4 字节 |
| `double` | 8 字节 |
| 指针 | 8 字节 |

#### 字节序

当一个对象由多个字节组成时，系统需要约定这些字节在内存中的排列顺序。假设整数 `0x01234567` 从地址 `0x100` 开始存放，它由 `01`、`23`、`45`、`67` 四个字节组成。

大端法将**最高**有效字节放在最低地址处：

```text
地址  0x100  0x101  0x102  0x103
内容    01     23     45     67
```

小端法将**最低**有效字节放在最低地址处：

```text
地址  0x100  0x101  0x102  0x103
内容    67     45     23     01
```

#### 字符串的表示

C 语言字符串由字符数组表示，并以空字符 `\0` 结尾：

```c
char str[] = "12345";
```

在使用 ASCII 编码的系统中，它的字节表示为：

```text
31 32 33 34 35 00
```

普通 ASCII 字符串以单字节字符为基本单位，因此通常不受字节序影响。

### 位运算

C 语言提供按位与 `&`、按位或 `|`、按位异或 `^`、按位取反 `~`、左移 `<<` 和右移 `>>` 运算。

假设只观察 4 个二进制位：

```text
x = 0110
y = 1010

x & y = 0010
x | y = 1110
x ^ y = 1100
~x    = 1001
```

记录了一些**特殊操作**

```c
int low_byte = x & 0xFF; // 读取最低 8 位
x = x | 0x1;             // 将最低位置 1
x = x & ~0x1;            // 将最低位清零
x = x ^ 0x1;             // 翻转最低位
```

```c
int a, b;
a ^ b = ~(~(a & ~b) & ~(~a & b));
int x;
!a = ((x | (~x + 1)) >> 31) + 1;
```

#### 逻辑运算与位运算

逻辑运算符 `&&`、`||` 和 `!` 将零视为假，将非零值视为真，结果只有 `0` 或 `1`。位运算则分别计算每一个二进制位。

```c
0x41 && 0x01 // 结果为 1
0x41 & 0x01  // 结果为 0x01
```

逻辑与和逻辑或还具有短路求值的特性。例如，当 `p == NULL` 时，下面表达式的右半部分不会执行：

```c
p != NULL && *p == 42
```

#### 移位运算

`x << k` 将 `x` 左移 $k$ 位并在右侧补零。在数值没有溢出的理想情况下，它相当于乘以 $2^k$。

右移有两种形式：

- **逻辑右移**：*左侧补零*，通常用于无符号数。
- **算术右移**：*左侧复制符号位*，通常用于补码有符号数。

```text
逻辑右移：101101 >> 2 = 001011
算术右移：101101 >> 2 = 111011
```

在 C 语言中，无符号数右移采用逻辑右移。有符号负数的右移结果由实现定义，现代编译器和机器通常采用算术右移。对负的有符号整数进行左移，或者左移后结果超出有符号类型范围，都可能导致未定义行为。

## 整数

### 整数的表示

#### 无符号整数

对于一个 $w$ 位二进制向量 $\vec{x}=[x_{w-1},x_{w-2},\ldots,x_0]$，它表示的无符号整数为：

$$
B2U_w(\vec{x})=\sum_{i=0}^{w-1}x_i2^i
$$

$w$ 位无符号整数的范围为：

$$
0\leq x\leq 2^w-1
$$

eg. 8 位无符号整数的范围是 `0` 到 `255`。

#### 补码整数

现代计算机通常使用补码表示有符号整数。补码将最高位解释为负权重，其余位仍然是正权重：

$$
B2T_w(\vec{x})=-x_{w-1}2^{w-1}+\sum_{i=0}^{w-2}x_i2^i
$$

最高位也称为符号位。它为 `0` 时数值非负，为 `1` 时数值为负。$w$ 位补码整数的范围为：

$$
TMin_w=-2^{w-1},\qquad TMax_w=2^{w-1}-1
$$

例如，8 位补码整数的范围是 `-128` 到 `127`：

| 位模式 | 补码值 |
| --- | ---: |
| `00000000` | 0 |
| `00000001` | 1 |
| `01111111` | 127 |
| `10000000` | -128 |
| `11111110` | -2 |
| `11111111` | -1 |

注意到，补码范围是不对称的，最小值的绝对值比最大值大 `1`：

$$
|TMin_w|=TMax_w+1
$$

求一个补码数相反数的方法是按位取反再加一。

eg.

```text
 5   = 00000101
~5 = 11111010
-5 = 11111011
```

#### 有符号数与无符号数的转换

相同位宽的有符号数和无符号数互相转换时，底层位模式通常不变，只是解释方式发生变化。对于 $w$ 位补码整数 $x$：

$$
T2U_w(x)=
\begin{cases}
x, & x\geq 0 \\
x+2^w, & x<0
\end{cases}
$$

例如，8 位位模式 `11111111` 作为补码解释为 `-1`，作为无符号数解释为 `255`。

```c
int x = -1;
unsigned int y = (unsigned int)x;
```

在 `int` 为 32 位的环境中，`y` 通常等于 `4294967295`。有符号数和无符号数混合运算时尤其需要注意：C 语言可能先把有符号数转换为无符号数，从而产生看似反直觉的结果。

```c
int x = -1;
unsigned int y = 1;

// x 会被转换为一个很大的无符号数，因此表达式通常为假。
bool result = x < y;
```

#### 扩展与截断

将无符号数转换为位数更大的类型时，应在左侧补零，这称为**零扩展**：

```text
101101 → 00000000 00101101
```

将补码整数转换为位数更大的类型时，应在左侧复制符号位，这称为**符号扩展**：

```text
0101 → 00000101
1011 → 11111011
```

当一个整数被截断为更少的位时，高位会被丢弃，只保留最低位。对于无符号数，将 $w$ 位数截断为 $k$ 位的结果满足：

$$
x'=x\bmod 2^k
$$

补码整数截断后，需要将保留下来的位重新解释为补码，因此数值甚至正负号都可能改变：

```text
127：01111111
截断为 4 位：1111
按 4 位补码解释：-1
```

### 整数的运算

#### 加法与溢出

对于 $w$ 位无符号整数，加法结果只保留最低的 $w$ 位：

$$
x+_w^u y=(x+y)\bmod 2^w
$$

例如，使用 4 位无符号数计算 `14 + 5`：

```text
  1110  = 14
+ 0101  = 5
------
1 0011  = 19
```

对满足 $0\leqslant x, y <2^w$ 的整数，有：

$$
x+^u_wy=
\begin{cases}
  x+y, x+y <2^w \\
  x+y-2^w, 2^w \leqslant x+y < 2^{w+1}
\end{cases}
$$

最高位被截断后结果为 `0011`，即十进制 `3`。无符号加法可以通过结果是否小于某个操作数来检测溢出：

```c
unsigned sum = x + y;
bool overflow = sum < x;
```

补码加法在硬件上可以使用相同的加法器，只需将保留的低 $w$ 位解释为补码。以下两种情况会发生补码溢出：

- 两个正数相加，结果却是负数。
- 两个负数相加，结果却是非负数。

```text
  0111  = 7
+ 0011  = 3
------
  1010  = -6  // 正溢出
```

对满足 $-2^{w-1} \leqslant x, y \leqslant 2^{w-1} - 1$ 的整数，有：
$$
x+^{t}_{w}y=
\begin{cases}
x+y-2^w, 2^{w-1} \leqslant x+y\\
x+y, -2^{w-1} \leqslant x+y < 2^{w-1}\\
x+y+2^w, x+y < -2^{w-1}
\end{cases}
$$

需要区分机器的位级行为和 C 语言规则：硬件加法器通常会自然截断高位，但 ISO C 将有符号整数溢出规定为未定义行为，程序不能依赖它一定按补码环绕。

#### 取反与乘法

补码整数的相反数可以通过 `~x + 1` 得到，但最小补码整数是特殊情况。固定字长的位级计算会得到：

$$
-TMin_w=TMin_w
$$

原因是补码中没有与 $TMin_w$ 对应的正数。在 C 语言中对有符号 `TMin` 求负会溢出，属于未定义行为。

两个 $w$ 位整数相乘，完整结果最多需要 $2w$ 位。如果只保留低 $w$ 位，则结果为：

$$
x*_w y=(x\times y)\bmod 2^w
$$

因此，无符号乘法和补码乘法得到的低 $w$ 位模式相同，只是对位模式的解释不同。

编译器有时会将乘以常数转换为移位与加减法。例如：

$$
x\times14=x\times(8+4+2)
$$

对应的位运算形式为：

```c
(x << 3) + (x << 2) + (x << 1)
```

实际编程时通常应优先保证表达清晰，把这类优化交给编译器。

#### 除以 2 的幂

无符号整数除以 $2^k$ 可以通过逻辑右移 $k$ 位实现：

```c
x >> k
```

非负补码整数也可以使用算术右移。对于负数，常见的算术右移向负无穷方向舍入，而 C 语言整数除法向零舍入，因此需要先加入偏置：

```c
(x < 0 ? x + (1 << k) - 1 : x) >> k
```

例如，C 语言中的 `-7 / 2` 等于 `-3`，而采用算术右移的 `-7 >> 1` 在常见机器上等于 `-4`。

## 浮点数

### 浮点数的表示

整数只能表示离散的整数值，浮点数则可以近似表示很大、很小以及带有小数部分的数。它的基本思想类似科学计数法，但是要从二进制的思路去理解：

$$
V=M\times2^E
$$

其中 $M$ 是尾数，$E$ 是阶码。因为浮点数只能使用有限数量的位，所以大多数实数只能得到近似表示。

#### 二进制小数

二进制小数点右侧各位的权重依次为 $2^{-1}$、$2^{-2}$、$2^{-3}$ 等。例如：

$$
(101.101)_2=2^2+2^0+2^{-1}+2^{-3}=5.625
$$

能够被有限二进制小数精确表示的数可以写成 $x/2^k$ 的形式。例如 `0.5`、`0.25` 和 `0.75` 都能被精确表示，而十进制 `0.1` 的二进制形式是无限循环小数。

#### IEEE 标准

IEEE 标准告诉我们，浮点数由符号位、阶码字段和小数字段组成：

```text
符号位 s | 阶码字段 exp | 小数字段 frac
```

其数值可以统一写为：

$$
V=(-1)^s\times M\times2^E
$$

常见的单精度和双精度格式如下：

| 格式 | 总位数 | 符号位 | 阶码位 | 小数位 |
| --- | ---: | ---: | ---: | ---: |
| 单精度 `float` | 32 | 1 | 8 | 23 |
| 双精度 `double` | 64 | 1 | 11 | 52 |

如果阶码字段有 $k$ 位，其偏置量为：

$$
Bias=2^{k-1}-1
$$

单精度的偏置量为 `127`，双精度的偏置量为 `1023`。

#### 规格化数

当阶码字段既不全为 `0`，也不全为 `1` 时，浮点数是规格化数。设阶码字段的无符号值为 $e$，小数字段表示的二进制小数为 $f$，则：

$$
E=e-Bias,\qquad M=1+f
$$

规格化数的尾数存在一个隐含的最高位 `1`，因此形如 `1.frac`。隐含位不需要实际存储，相当于额外获得一位精度。

#### 非规格化数

当阶码字段全为 `0` 时，浮点数是非规格化数：

$$
E=1-Bias,\qquad M=f
$$

它的尾数没有隐含的最高位 `1`，形如 `0.frac`。非规格化数可以表示零以及非常接近零的数，从而实现逐渐下溢。

浮点数存在正零和负零：

```text
+0：s = 0，exp 全为 0，frac 全为 0
-0：s = 1，exp 全为 0，frac 全为 0
```

通常有 `+0.0 == -0.0`，但它们在某些运算中的结果不同，例如 `1 / +0.0` 得到正无穷，而 `1 / -0.0` 得到负无穷。

#### 无穷大与 NaN

当阶码字段全为 `1` 时：

- 小数字段全为 `0`，表示正无穷或负无穷。
- 小数字段不全为 `0`，表示 NaN（Not a Number）。

`0.0 / 0.0`、$\infty-\infty$ 或对负数开平方等运算可能产生 NaN。NaN 与任何数进行相等比较都为假，包括它自身，因此应使用 `isnan` 判断 NaN。

| 阶码字段 | 小数字段 | 类型 |
| --- | --- | --- |
| 全为 `0` | 全为 `0` | `+0` 或 `-0` |
| 全为 `0` | 不全为 `0` | 非规格化数 |
| 不全为 `0` 且不全为 `1` | 任意 | 规格化数 |
| 全为 `1` | 全为 `0` | `+∞` 或 `-∞` |
| 全为 `1` | 不全为 `0` | NaN |

注：不用从数学的角度去强行理解NaN，他只是一种特殊的表示，来记录那些无法用实数表示的数学值。

### 浮点数的换算与舍入

#### 十进制与二进制的换算

十进制整数转换为二进制时，可以不断除以 `2` 并逆序排列余数。例如：

```text
13 / 2 = 6  余 1
 6 / 2 = 3  余 0
 3 / 2 = 1  余 1
 1 / 2 = 0  余 1

13₁₀ = 1101₂
```

十进制小数转换为二进制时，可以不断乘以 `2`，依次记录结果的整数部分：

```text
0.625 × 2 = 1.25 → 1
0.25  × 2 = 0.5  → 0
0.5   × 2 = 1.0  → 1

0.625₁₀ = 0.101₂
```

如果这个过程不能结束，就说明该十进制小数不能被有限二进制小数精确表示。

#### 转换为 IEEE 表示

以 `0.15625` 的单精度表示为例。首先转换为二进制并规格化：

```text
0.15625 = 0.00101₂ = 1.01₂ × 2⁻³
```

由此得到：

```text
s = 0
E = -3
M = 1.01₂
```

单精度偏置为 `127`，所以阶码字段的值为：

$$
e=E+Bias=-3+127=124=(01111100)_2
$$

去掉尾数中隐含的最高位 `1` 后，小数字段为 `01000000000000000000000`。最终位模式为：

```text
0 01111100 01000000000000000000000
```

写成十六进制即 `0x3E200000`。

#### 舍入方式

因为目标格式的位数有限，不能精确表示的结果需要舍入。IEEE 定义了以下舍入方式：

- 向偶数舍入，即就近舍入，恰好位于中间时选择最低有效位为 `0` 的结果。
- 向零舍入。
- 向正无穷舍入。
- 向负无穷舍入。

默认方式通常是向偶数舍入。假设舍入到整数：

```text
1.4 → 1
1.6 → 2
1.5 → 2
2.5 → 2
3.5 → 4
```

当数值恰好位于两个结果中间时选择偶数，可以减少大量舍入操作整体偏向某个方向的统计误差。

硬件在浮点运算中通常还会保留额外的 Guard、Round 和 Sticky 位：

- **Guard 位**：目标精度后的第一位。
- **Round 位**：目标精度后的第二位。
- **Sticky 位**：更低的所有位进行逻辑或得到的结果。

这些额外位用于判断精确结果位于两个可表示数之间的什么位置。

#### 整数与浮点数之间的转换

- `int` 转换为 `float` 通常不会溢出，但可能被舍入。单精度只有 24 位有效精度，因此无法精确表示所有 32 位整数。
- `int` 转换为 `double` 时，所有 32 位整数通常都能被精确表示，因为双精度有 53 位有效精度。
- `float` 或 `double` 转换为整数时，小数部分通常会被丢弃，即向零舍入；超出目标整数范围时不能依赖一个可移植的结果。

例如：

```c
int x = 16777217; // 2^24 + 1
float f = x;       // 通常舍入为 16777216

int a = (int)3.9;  // 3
int b = (int)-3.9; // -3
```

### 浮点数的运算

#### 浮点加法

计算两个浮点数之和通常包含以下步骤：

1. 比较阶码并完成对阶。
2. 对尾数进行加法或减法。
3. 将结果重新规格化。
4. 按目标精度舍入。
5. 检查上溢、下溢和特殊值。

例如：

$$
1.0\times2^3+1.0\times2^1
=1.0\times2^3+0.01\times2^3
=1.01\times2^3
$$

当两个操作数的数量级相差很大时，较小数的有效位可能在对阶过程中被全部舍弃。因此，`1e20 + 1.0` 在常见浮点格式中可能仍然等于 `1e20`。

#### 浮点乘法

若两个浮点数分别为：

$$
x=(-1)^{s_x}M_x2^{E_x},\qquad
y=(-1)^{s_y}M_y2^{E_y}
$$

它们乘积的符号、尾数和阶码分别为：

$$
s=s_x\oplus s_y,\qquad M=M_xM_y,\qquad E=E_x+E_y
$$

完成计算后同样需要规格化、舍入，并检查上溢、下溢和特殊值。

#### 浮点运算的性质

浮点运算是对实数运算的近似。每一步都可能发生舍入，所以一些实数运算规律在浮点数中不再总是成立。

浮点加法不满足结合律。例如：

```c
double x = 1e20;
double y = -1e20;
double z = 3.14;
```

可能得到：

```text
(x + y) + z = 3.14
x + (y + z) = 0.0
```

原因是计算 `y + z` 时，`z` 相对于 `y` 太小，在舍入过程中被丢失。类似地，浮点乘法不一定满足结合律，分配律也可能因为舍入、上溢或下溢而不成立。

#### 浮点数比较

十进制 `0.1` 和 `0.2` 通常不能被二进制浮点数精确表示，因此不应随意使用 `==` 比较浮点计算结果：

```c
double x = 0.1 + 0.2;

if (x == 0.3) {
    // 不一定执行
}
```

更常见的做法是判断绝对误差和相对误差是否在允许范围内：

```c
#include <math.h>
#include <stdbool.h>

bool nearly_equal(double a, double b,
                  double abs_epsilon,
                  double rel_epsilon) {
    double diff = fabs(a - b);

    if (diff <= abs_epsilon) {
        return true;
    }

    return diff <= rel_epsilon * fmax(fabs(a), fabs(b));
}
```

使用浮点数时还应注意：

- 运算顺序可能影响最终结果。
- 大数与很小的数相加时，小数可能被舍弃。
- 多次累计运算会积累误差。
- 判断 NaN 和无穷大时应使用 `isnan` 和 `isinf`。
- 金额等需要精确十进制结果的数据通常更适合使用整数、定点数或十进制数据类型。
